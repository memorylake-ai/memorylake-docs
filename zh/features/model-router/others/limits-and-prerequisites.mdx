## 您需要提前准备的内容
- 已创建账户并登录。
- 在[控制台](https://app.memorylake.ai/panel/token)中至少创建了一个 API Key，并将其关联到正确的 API Key 分组或团队上下文。
- 对应分组已配置可用模型、通道和基础配额（详情请参阅"团队协作 / 配额与用量"）。

## 模型与通道限制
- **按 API Key 隔离**：
  每个 API Key 只能查看和调用其所属分组下配置的模型和通道；同一平台上不同 API Key 的模型列表可能完全不同。
- **模型目录是权威来源**：
  `/v1/models`、`/claude/v1/models`、`/gemini/*/models` 返回的列表代表当前 API Key 真正可用的模型和来源；不在列表中的模型视为不可用。
- **多模态与任务通道**：
  Midjourney、Suno、RecraftAI 和 Kling 等基于任务的能力依赖于对应通道的启用。未启用时，相关的任务接口将不可用。

## 配额与计费限制
- **配额不足立即拒绝**：
  在配额预扣费阶段，如果任何一方（个人、团队或所有者）配额不足，请求将被直接拒绝，不会进入模型执行阶段。
- **预扣费与结算两阶段**：
  请求发起时预扣配额，请求完成后根据实际使用量结算；失败的请求不会消耗额外配额。
- **独立的配额空间**：
  不同 API Key / 团队 / 上下文的配额相互独立、互不干扰；切换上下文时，请确认当前使用的是哪个配额空间。

## 协议与入口限制
- OpenAI 兼容入口：
  `/v1/*` 系列接口仅接受 OpenAI 风格的请求体和字段；如果使用 Claude 或 Gemini 官方 SDK，建议优先使用各自的原生路径。
- 原生路径：
  `/claude/v1/messages`、`/gemini/:version/models/:model` 等路径遵循各自的协议规则；字段和模型 ID 与官方版本兼容，但调用成功仍取决于 API Key 可见的模型限制。
- 任务接口：
  Midjourney、Suno、RecraftAI、Kling 等接口使用异步的"任务 ID + 查询"模式，不保证在单次请求中返回最终的图片、音频或视频。

## 速率与稳定性限制
- **速率限制与 429**：
  为保护稳定性，平台根据配置对主要路由和任务接口进行速率限制；超出时可能返回 429 或相关错误，需要客户端进行重试或退避。
- **通道健康状态**：
  自动重试和通道切换依赖于至少一个健康的备用通道；当所有相关通道不可用时，请求仍可能失败。
- **长时间流式调用**：
  流式响应在网络异常或超时时将被关闭；请在客户端预留超时和重连策略。

## 权限与上下文限制
- **上下文类型**：
  调用在个人（用户）或团队（团队）上下文下执行，不同上下文对应不同的配额和模型可见范围。
- **角色与权限**：
  是否能管理团队配额、查看团队用量或调整成员配额，取决于团队角色和权限配置（详情请参阅"团队协作 / 角色与权限"）。
- **日志可见范围**：
  日志和用量统计按上下文和权限控制可见性；普通成员无法查看权限范围之外的调用记录。

## 与其他功能的关系
- **配额与用量**：
  所有调用（包括多模态和任务）都会反映在用量和配额视图中；配额拦截逻辑与团队协作中的配额规则一致。
- **安全与通知**：
  内容审核和告警通知依赖于控制台中的相应配置；未配置时，仅通过返回的错误和控制台日志体现。

## 使用前检查清单
1) 在[控制台](https://app.memorylake.ai/panel)中，确认当前 API Key 的分组、上下文（个人/团队）和基础配额。
2) 通过模型目录接口，确认目标模型是否在当前 API Key 的可见列表中。
3) 如果使用 Midjourney、Suno、RecraftAI、Kling 等任务接口，请先确认管理员已启用对应通道。
4) 集成前，估算调用量并在团队配额中预留充足配额，以避免频繁触发配额不足或速率限制。
