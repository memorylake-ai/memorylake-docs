---
title: "通过 MCP 连接"
description: "用标准 OAuth2 将 Claude Code、Codex、Cursor 等 MCP 客户端连接到 MemoryLake"
---

MemoryLake 运行着一个**远程 MCP 服务器**，任何支持 MCP 的客户端都可以通过 HTTP 连接。授权采用标准 **OAuth2**——您无需把任何密钥粘贴到配置文件中，并可在授权页面选择该客户端可访问的工作空间和 Boundary。

## 服务器 URL

```text
https://app.memorylake.ai/memorylake/mcp/v2
```

在[控制台](https://app.memorylake.ai)打开一个工作空间，选择 **MCP** 标签页：这里展示该 URL 并提供复制按钮，同时给出各客户端的现成接入步骤。（旧的 **集成 → MCP** 链接现在会跳到这个标签页。）

<Info>
连接页面没有项目选择器。授权时，授权页面会让您依次选择**个人 / 团队**、**工作空间**和**记忆边界**——这决定了该客户端能读写哪些内容。
</Info>

## 连接您的客户端

<Tabs>
<Tab title="Claude Code">
在终端添加服务器（`--scope user` 可选，加上后在所有项目中可用）：

```bash
claude mcp add --transport http --scope user memorylake https://app.memorylake.ai/memorylake/mcp/v2
```

然后授权：在终端运行 `claude` 进入会话，输入 `/mcp`，选中 `memorylake` 后选择 **Authenticate**，浏览器会打开授权页。Claude Code 没有独立的登录命令，授权只能在会话内触发。

用 `claude mcp list` 验证：`memorylake` 一行应显示 `✓ Connected`。
</Tab>

<Tab title="Codex">
在终端添加服务器。`--url` 表示这是一个 streamable HTTP 服务器，默认走 OAuth：

```bash
codex mcp add memorylake --url https://app.memorylake.ai/memorylake/mcp/v2
```

这条命令会把配置写进 `~/.codex/config.toml` 的 `[mcp_servers.memorylake]`。然后登录，浏览器会打开授权页：

```bash
codex mcp login memorylake
```

用 `codex mcp list` 验证。
</Tab>

<Tab title="Cursor">
写进 `~/.cursor/mcp.json`（全局可用）或项目里的 `.cursor/mcp.json`（只对该项目生效），保存后 Cursor 会自动重新加载。控制台 **MCP** 标签页里也有「一键装进 Cursor」按钮可自动写入。

```json
{
  "mcpServers": {
    "memorylake": {
      "url": "https://app.memorylake.ai/memorylake/mcp/v2"
    }
  }
}
```

打开 **Settings → MCP**，`memorylake` 会提示需要登录；点击登录，浏览器会打开授权页。
</Tab>

<Tab title="VS Code">
写进工作区的 `.vscode/mcp.json`，或用命令面板执行 **MCP: Add Server**。控制台 **MCP** 标签页里也有「一键装进 VS Code」按钮。

```json
{
  "servers": {
    "memorylake": {
      "type": "http",
      "url": "https://app.memorylake.ai/memorylake/mcp/v2"
    }
  }
}
```

启动该服务器时 VS Code 会提示授权，确认后浏览器会打开授权页。
</Tab>

<Tab title="Claude Desktop">
打开 **Settings → Connectors → Add custom connector**，把上面的服务器 URL 粘贴进去。确认添加后 Claude Desktop 会弹出授权窗口，按提示完成登录与授权。
</Tab>

<Tab title="其他客户端">
任何支持 OAuth 2.1 的远程 MCP 客户端都可以使用。把它指向上面的服务器 URL 即可——不需要 API Key，也不需要自定义 header。首次收到 `401` 后，客户端会自动发现授权服务器、动态注册自身、通过 PKCE 走浏览器授权，并自行续期 token。
</Tab>
</Tabs>

## 已连接客户端能做什么

授权完成后，客户端将获得用于搜索和分析作用域内内容的工具：

| 工具 | 功能 |
|---|---|
| `search_memory` | 在记忆和文档中执行关键词 + 语义混合搜索 |
| `fetch_memory` | 获取特定结果的详细元数据与下载链接 |
| `get_memorylake_metadata` | 概览——按类型统计文件数、电子表格的 sheet 名称、文档统计 |
| `create_memory_code_runner` / `run_memory_code` | 沙箱化 Python（pandas、numpy 等）处理作用域内的文件，状态在多次调用间保持 |
| `nl_query_database` | 对已连接的数据库执行自然语言 SQL（需已配置数据库） |

OpenAI 协议的客户端会自动获得这些工具的简化版 `search` / `fetch` 变体——同一个端点自适应不同客户端。

这些工具只做读取与分析；它们不会修改或删除您的文档和记忆。

## 管理访问权限

- **换工作空间**：个人/团队空间和工作空间在授权时就写进了 token，事后改不了。要换一个，先从客户端删掉该 MCP 服务器，再重新添加并重新授权（以 Claude Code 为例：`claude mcp remove memorylake`，再执行上面的 `claude mcp add` 命令，然后在会话里用 `/mcp` 重新 **Authenticate**）。
- **撤销**：在控制台 **账号设置 → 登录与安全 → 已授权的应用** 中撤销该客户端。如需同时从客户端移除，Claude Code 执行 `claude mcp remove memorylake`。
- **Token 有效期**：访问 token 生命周期很短，由客户端自动刷新。

<Note>
早期版本的 MemoryLake 使用 v1 MCP 端点，需要把项目级 Key 嵌入 URL（`…/mcp/v1?apikey=…`）。该方式已下线：控制台不再创建 v1 端点或 Key，也不能用 API Key 连接 MCP。v1 端点仍保留，仅供已有集成继续使用；新连接请使用上面的 v2 URL。API Key 仍用于 REST API。
</Note>

## 故障排查

<AccordionGroup>
<Accordion title="客户端无法连接">
确认 URL 以 `/mcp/v2` 结尾，且客户端配置的是**远程 HTTP** MCP 服务器（而不是本地命令）。同时确认客户端支持 MCP 的 OAuth2——只接受静态 token 的旧客户端无法使用 v2 端点。
</Accordion>

<Accordion title="授权成功但看不到工具">
检查是否在授权页面完成了个人/团队、工作空间和记忆边界的选择，然后重新授权一次（Claude Code：在会话里 `/mcp` → **Authenticate**；Codex：`codex mcp login memorylake`；其他客户端在各自的 MCP 设置里重新登录）。
</Accordion>

<Accordion title="浏览器没有自动弹出授权页">
终端会打印一条包含 `/oauth2/mcp/authorize` 的链接，手动复制到浏览器打开即可。SSH 或远程开发环境基本都是这种情况。
</Accordion>

<Accordion title="工具没有返回任何结果">
您授权的记忆边界可能指向了一个空项目。请在控制台确认该记忆边界里的项目中确实有文档或记忆。
</Accordion>

<Accordion title="我的控制台里看不到 MCP">
MCP 的可用性取决于您的部署环境。如果工作空间里没有 **MCP** 标签页，或标签页提示当前部署未启用 OAuth2 MCP，请联系 [support@memorylake.ai](mailto:support@memorylake.ai)。
</Accordion>
</AccordionGroup>
