## 什么是资料库？

**资料库（Library）**是一个统一的文件系统，保存 MemoryLake 可以访问的所有文件。项目文档始终通过引用资料库中已有的文件来创建。

你的顶级可写文件夹是 **`MY_SPACE`** — 将其视为工作空间的根目录。你创建的每个文件或文件夹都放置在 `MY_SPACE` 下（直接放置或嵌套在子文件夹中）。

典型的集成流程如下：

<Steps>
<Step title="选择目标文件夹">
使用别名 `MY_SPACE` 直接定位工作空间根目录，或传入你在其下创建的任何子文件夹的 `item_id`。
</Step>
<Step title="将文件上传到资料库">
分块上传：[创建上传会话](/zh/features/memorylake/api-reference/library/create-upload)，PUT 每个分块，然后[创建文件项](/zh/features/memorylake/api-reference/library/create-item)。
</Step>
<Step title="将文件导入项目">
使用上一步返回的 `item_id` 调用[导入文档](/zh/features/memorylake/api-reference/v3-documents/import-documents)。
</Step>
</Steps>

## 基础 URL

```
https://app.memorylake.ai/openapi/memorylake
```

## 项目 ID 别名

在任何接受 `item_id` 的地方，你可以传入别名 `MY_SPACE` 来代替具体的 ID。

`MY_SPACE` 始终解析为你的工作空间根目录。当你需要查找根文件夹时，可以直接传入它 — 例如在创建顶级文件或文件夹时作为 `parent_item_id` 使用。

<Tip>
你不需要先调用 [Get Item](/zh/features/memorylake/api-reference/library/get-item) 来获取根文件夹 — 直接使用 `MY_SPACE` 即可。
</Tip>

## 上传文件（端到端流程）

文件采用分块上传方式。你会收到每个分块对应的一个预签名 PUT URL，逐块上传后，最后通过创建一个引用该上传的 `file` 项来完成。

<Steps>
<Step title="创建上传会话">
`POST /api/v1/drives/items/upload`，传入 `file_size`（字节数）。返回一个 `upload_id` 和一个 `part_items` 列表 — 每个分块对应一个预签名 URL。
</Step>
<Step title="上传每个分块">
将每个分块的字节 `PUT` 到其 `upload_url`。保存每次响应中的 `ETag` 头 — 你需要收集所有的 ETag。
</Step>
<Step title="创建文件项">
`POST /api/v1/drives/items`，传入 `item_type: "file"` 和 `from: { upload_id, part_etags }`。返回新的 `item_id`。
</Step>
</Steps>

### Python 示例

```python
import os, requests

BASE = "https://app.memorylake.ai/openapi/memorylake/api/v1"
HEADERS = {"Authorization": "Bearer sk_xxxxxx"}

def upload_file_to_library(path: str, parent_item_id: str = "MY_SPACE") -> str:
    """Upload a local file into the Library and return its item_id."""
    size = os.path.getsize(path)

    # 1. Create upload session — get pre-signed URLs
    init = requests.post(
        f"{BASE}/drives/items/upload",
        headers={**HEADERS, "Content-Type": "application/json"},
        json={"file_size": size},
    ).json()["data"]

    # 2. PUT each chunk; collect ETags
    part_etags = []
    with open(path, "rb") as f:
        for part in init["part_items"]:
            chunk = f.read(part["size"])
            resp = requests.put(part["upload_url"], data=chunk)
            part_etags.append({"number": part["number"], "etag": resp.headers["ETag"]})

    # 3. Create the file item
    created = requests.post(
        f"{BASE}/drives/items",
        headers={**HEADERS, "Content-Type": "application/json"},
        json={
            "item_type": "file",
            "parent_item_id": parent_item_id,
            "name": os.path.basename(path),
            "from": {"upload_id": init["upload_id"], "part_etags": part_etags},
        },
    ).json()["data"]

    return created["item_id"]
```

## 名称冲突

创建文件或文件夹时，可以在请求中选择冲突处理策略：

| 策略 | 行为 | `item_id` |
|---|---|---|
| `rename`（默认） | 追加 `_N` 后缀（`report_1.pdf`）。始终成功。 | 新 ID |
| `deny` | 如果名称已被占用，返回 `409 DRIVE_ITEM_CONFLICT`。 | — |
| `overwrite` | 仅限文件。就地覆盖现有文件的内容。 | **保留原 ID** |
| `replace` | 仅限文件。删除现有文件并创建新文件。 | 新 ID |

<Warning>
`overwrite` 和 `replace` 并非同义词。`overwrite` 保留现有的 `item_id`；`replace` 会分配一个新的 ID。两个选项都不会重新处理已从该文件导入的项目文档 — 如果你需要索引新内容，请重新调用[导入文档](/zh/features/memorylake/api-reference/v3-documents/import-documents)。
</Warning>
