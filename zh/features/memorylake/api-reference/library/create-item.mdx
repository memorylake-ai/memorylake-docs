---
title: "创建项目"
description: "创建文件夹，或在上传分块后注册文件"
---

```
POST /openapi/memorylake/api/v1/drives/items
```

一个接口，两种模式 — 通过 `item_type` 字段选择：

- **文件夹** (`item_type: "folder"`) — 在资料库中创建一个空文件夹。
- **文件** (`item_type: "file"`) — 注册一个字节已通过分块上传存储的文件。你必须先调用[创建上传](/zh/features/memorylake/api-reference/library/create-upload)并收集每个分块的 `ETag`。

选择下方与你要创建的项类型匹配的标签页。不同模式的必填字段不同。

<Note>
`parent_item_id` 接受别名 `MY_SPACE`（你的工作空间根目录）。直接传入即可，无需查找根目录 ID。你也可以传入任何文件夹的 `item_id` 来创建更深层级的项。
</Note>

<Note>
**所需权限：** [`drive:item_add`](/features/team-collaboration/permission-reference#upload-and-create-files) · `service`

**流程说明（文件模式）：** 以 `item_type: "file"` 模式调用此接口是资料库上传流程的第 2 步；第 1 步是[创建上传](/zh/features/memorylake/api-reference/library/create-upload)（相同权限）。如需将文件添加到项目中，请调用[导入文档](/zh/features/memorylake/api-reference/v3-documents/import-documents) — 该操作还需要 [`project:doc_add`](/features/team-collaboration/permission-reference#add-a-document-to-a-project) 权限。
</Note>

### 请求体

<Tabs>
<Tab title="创建文件夹">

<ParamField body="item_type" type="string" required>
必须为 `"folder"`。
</ParamField>

<ParamField body="parent_item_id" type="string" required>
父文件夹 — `MY_SPACE` 或任何文件夹的 `item_id`。
</ParamField>

<ParamField body="name" type="string" required>
文件夹名称，例如 `Q2 Reports`。
</ParamField>

<ParamField body="name_conflict_strategy" type="string" default="rename">
当 `parent_item_id` 中已存在同名项时的行为：

- `rename`（默认） — 追加数字后缀（`Q2 Reports_1`）。
- `deny` — 返回 `409 DRIVE_ITEM_CONFLICT` 错误。
</ParamField>

<ParamField body="x_attrs" type="object">
扩展属性 — 用于调用方自定义元数据的 `字符串 → 字符串` 映射。
</ParamField>

</Tab>
<Tab title="创建文件">

此调用完成你之前发起的上传 — 不会传输字节。在到达此步之前，你应该已经：

1. 调用[创建上传](/zh/features/memorylake/api-reference/library/create-upload)并传入 `file_size`，接收到 `upload_id` 和每个分块的预签名 URL。
2. 将每个分块 PUT 到其 URL，并保存每次响应的 `ETag` 头。

<ParamField body="item_type" type="string" required>
必须为 `"file"`。
</ParamField>

<ParamField body="parent_item_id" type="string" required>
父文件夹 — `MY_SPACE` 或任何文件夹的 `item_id`。
</ParamField>

<ParamField body="name" type="string" required>
文件名称，例如 `report.pdf`。
</ParamField>

<ParamField body="from" type="object" required>
已完成分块上传的引用。

<Expandable title="from">
  <ParamField body="upload_id" type="string" required>
  [创建上传](/zh/features/memorylake/api-reference/library/create-upload)返回的 `upload_id`。
  </ParamField>
  <ParamField body="part_etags" type="array" required>
  每个已上传分块对应一个条目。必须按顺序包含所有分块。

  <Expandable title="part_etags item">
    <ParamField body="number" type="integer" required>
    分块编号（从 1 开始）。必须与上传会话中的 `number` 匹配。
    </ParamField>
    <ParamField body="etag" type="string" required>
    PUT 该分块时返回的 `ETag` 头值。
    </ParamField>
  </Expandable>
  </ParamField>
</Expandable>
</ParamField>

<ParamField body="name_conflict_strategy" type="string" default="rename">
当 `parent_item_id` 中已存在同名项时的行为：

- `rename`（默认） — 追加数字后缀（`report_1.pdf`）。
- `deny` — 返回 `409 DRIVE_ITEM_CONFLICT` 错误。
- `overwrite` — 覆盖资料库中现有文件的内容。现有的 `item_id` **保持不变**。
- `replace` — 删除现有文件并创建新文件。分配**新的 `item_id`**；对旧 ID 的引用将失效。
</ParamField>

<Warning>
`overwrite` 仅替换资料库中存储的文件字节 — **不会**重新处理或重新索引之前从该文件导入的任何项目文档。要将新内容传播到项目中，请在覆盖后再次调用[导入文档](/zh/features/memorylake/api-reference/v3-documents/import-documents)（或使用新文件）。
</Warning>

<ParamField body="x_attrs" type="object">
扩展属性 — 用于调用方自定义元数据的 `字符串 → 字符串` 映射。
</ParamField>

</Tab>
</Tabs>

<RequestExample>
```bash Create folder
curl -X POST 'https://app.memorylake.ai/openapi/memorylake/api/v1/drives/items' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "item_type": "folder",
    "parent_item_id": "MY_SPACE",
    "name": "Q2 Reports"
  }'
```

```bash Create file
curl -X POST 'https://app.memorylake.ai/openapi/memorylake/api/v1/drives/items' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "item_type": "file",
    "parent_item_id": "MY_SPACE",
    "name": "report.pdf",
    "from": {
      "upload_id": "upl-abc123def456",
      "part_etags": [
        { "number": 1, "etag": "d41d8cd98f00b204e9800998ecf8427e" },
        { "number": 2, "etag": "f6e5d4c3b2a10987f6e5d4c3b2a10987" }
      ]
    }
  }'
```
</RequestExample>

### 响应

文件夹和文件的响应结构相同。

<ResponseField name="data" type="object">
<Expandable title="已创建的项">
  <ResponseField name="uri" type="string">已创建项的 Drive 资源 URI</ResponseField>
  <ResponseField name="item_id" type="string">结果项的 ID。使用 `overwrite` 时，等于现有文件的 `item_id`（保留）。使用 `replace`、`rename` 或全新创建时，分配新的 `item_id`。</ResponseField>
  <ResponseField name="name" type="string">实际名称。当 `rename` 策略产生自动后缀时，与请求中的 `name` 不同。</ResponseField>
</Expandable>
</ResponseField>

<ResponseExample>
```json Success (200)
{
  "success": true,
  "data": {
    "uri": "drive://items/sc-5c6bf0f82d624a20a6fa4696997bdd46:7d8cf1e93f634b31b5",
    "item_id": "sc-5c6bf0f82d624a20a6fa4696997bdd46:7d8cf1e93f634b31b5",
    "name": "report.pdf"
  }
}
```
</ResponseExample>

<Tip>
始终从响应中读取 `name`。使用默认的 `rename` 策略时，服务器可能已追加后缀 — 返回的 `name` 才是你应该显示和存储的名称。
</Tip>
