## 背景与价值

- 平台使用 API Key 作为唯一调用凭证。所有请求首先验证配额、过期时间和状态，防止透支或滥用。
- 兼容 OpenAI / Claude / Gemini 调用格式，只需替换 Base URL 和 Token 即可复用现有客户端。

## 适用场景

- 首次集成，想确认如何携带 Token 和调用路径。
- 团队或多客户端共享统一入口，需要控制配额。
- 想在配额不足或路由不可用时获得清晰反馈，便于自行诊断。

## 核心能力

- **Token 管理**：在[控制台](https://app.memorylake.ai/panel/token)生成 API Key，可设置配额、过期时间和启用状态。请求首先验证这些条件；不满足条件时直接拒绝。
- **配额与预扣**：每次请求预扣配额；成功返回确认扣除，失败回滚预扣，确保配额精确。
- **多模型兼容**：支持 OpenAI `/v1`、Claude `/claude/v1` 和 Gemini `/gemini/:version` 的路径和参数格式。
- **通用请求头规则**：根据兼容端点携带 Token：
  - OpenAI 兼容：`Authorization: Bearer sk-xxx`
  - Claude 兼容：`x-api-key: sk-xxx`
  - Gemini 兼容：`x-goog-api-key: sk-xxx`
- **日志可见字段**：调用记录模型、Token 名称、渠道、请求延迟（`request_time`）、提示/完成令牌数等，便于排查和对账。

## 关键使用要点

1) **获取 Token**：在[控制台](https://app.memorylake.ai/panel/token)创建 API Key，设置配额和过期时间；确保状态为启用。
2) **选择端点和 Base**：将客户端的 API Base 替换为平台地址，如 `https://app.memorylake.ai`，遵循对应的兼容端点路径。
3) **携带请求头**：按照上述通用规则填写 Token 请求头；其他参数保持官方格式。
4) **发送请求**：可先调用 `GET /v1/models` 或对应的模型列表端点确认当前可用模型。
5) **查看结果**：请求成功后，在[日志](https://app.memorylake.ai/panel/log)中查看模型、渠道、延迟和令牌数；聚合统计按日期汇总用量和配额消费。

## 常见认证与配额注意事项

- **配额不足**：Token 配额不足时直接拒绝请求；检查配额或调整倍率后重试。
- **Token 无效**：过期或禁用的 Token 会拒绝请求；更新 Token 状态或重新生成。
- **无可用路由**：当目标模型在当前路由中不可用时会提示；切换模型或调整路由配置。
- **指定路由**：需要固定路由时，通过 Token 后缀或特定请求头约定（如已配置）指定；不指定则使用默认路由。

## 限制与注意事项

- 仅支持 API Key 作为调用凭证；不涉及账户登录方式。
- 配额验证覆盖配额、过期时间和状态；预扣在失败时回滚。
