## 背景与价值

您可以通过统一入口调用多种模型格式（OpenAI / Claude / Gemini），在不修改现有客户端的情况下实现一致体验。平台主动验证配额、记录关键日志，并支持代理和倍率，帮助您以可控、可观测的方式安全运营。

## 适用场景

- 想要快速切换到统一入口，同时继续使用现有的 OpenAI / Claude / Gemini 客户端。
- 需要在不同渠道之间设置倍率或模型通配符，以平衡成本和兼容性。
- 关注调用可见性：希望查看模型、Token、渠道、延迟、令牌等记录。
- 需要在受限网络中配置代理，或使用通知功能及时获取结果。

## 核心原则

- **兼容优先**：遵循 OpenAI `/v1`、Claude `/claude/v1` 和 Gemini `/gemini/:version` 的请求格式。您只需替换 Base URL 和 Token 即可调用。
- **配额可控**：每次调用验证并预扣配额；配额不足时立即拒绝。成功调用确认扣除，失败调用回滚预扣，确保消费可预测。
- **灵活路由**：模型支持通配符，渠道可设置倍率或代理。需要时可通过 Token 后缀或特定请求头指定路由，兼顾自动分发与精确控制。
- **透明可追溯**：日志记录模型名称、Token 名称、渠道、请求延迟（`request_time`）、提示和完成 Token 数等。统计数据按日期聚合调用次数、配额和延迟，便于对账和排查。
- **特殊能力透传**：支持 o1/o3 ReasoningEffort 选择、Claude thinking、Gemini 搜索和代码执行等官方参数透传，保持与各客户端的一致性。

## 关键使用要点

- 首次调用前，获取模型列表确认可用模型，然后使用测试 Token 验证倍率和通配符配置。
- 发送请求时，保持官方字段不变，仅替换 Base URL 和 Token。根据需要决定是否指定路由；否则使用默认自动路由。
- 关注配额状态：配额不足时会立即拒绝。需要持续调用时请提前补充。
- 调用后，查看日志和聚合统计，验证模型、Token、延迟和消费，识别异常或对账。

## 限制与注意事项

- 仅启用的模型和路由会被路由；禁用的模型或配额不足将被拒绝。
- 代理和倍率在渠道级别配置；效果取决于当前路由设置。
- 特殊能力需传递官方参数；未提供相应参数时使用默认行为。
