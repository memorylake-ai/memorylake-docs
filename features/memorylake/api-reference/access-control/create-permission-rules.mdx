---
title: "Create Permission Rules"
description: "Allows one or more actions on a resource for a custom role or a single member — one rule per action"
---

```
POST /openapi/memorylake/admin/v1/permission-rules
```

Allows one or more actions on a resource for a custom role or a single member — one rule per action. Only allow rules can be created; a deny (which would win over allows from any source except the owner) is not available — to take a permission away, delete the rule that grants it. The built-in roles cannot be changed, and actions that belong to the team owner cannot be granted. When an action depends on others the subject lacks, the request is refused with 409 unless auto_grant_prerequisites is set.

<Note>
**Permission required:** `policy:manage`
</Note>

### Headers

<ParamField header="Idempotency-Key" type="string">
Optional. Retrying with the same value replays the first result.
</ParamField>

### Request Body

<ParamField body="actions" type="array" required>
Actions to allow on the resource; one rule per distinct action
</ParamField>

<ParamField body="reason" type="string" required>
Why the change is made; recorded in the audit log
</ParamField>

<ParamField body="resource" type="string" required>
Resource type, e.g. memorylake:project (see GET /permission-catalog), or one instance as &lt;resource_type&gt;:&lt;instance_id&gt;. API key permissions are written on tenant:service_account:own or tenant:service_account:any.
</ParamField>

<ParamField body="subject_id" type="string" required>
A custom role key of this team, or a member's principal_id. The built-in roles cannot be changed.
</ParamField>

<ParamField body="subject_type" type="string" required>
role or member
</ParamField>

<ParamField body="auto_grant_prerequisites" type="boolean">
When an action needs others the subject lacks (e.g. modify needs read), add those too. Without it such a request is refused with 409 naming what is missing.
</ParamField>

<ParamField body="effect" type="string" default="allow">
allow. Deny rules cannot be created: to take a permission away, delete the rule that grants it.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST 'https://app.memorylake.ai/openapi/memorylake/admin/v1/permission-rules' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Idempotency-Key: 7c1d2e3f-0a9b-4c8d-b7e6-f5a4d3c2b1a0' \
  -H 'Content-Type: application/json' \
  -d '{
    "actions": [
      "example"
    ],
    "reason": "example",
    "resource": "example",
    "subject_id": "8488f48135da0a123c4c74cad0b8fbbc",
    "subject_type": "role",
    "auto_grant_prerequisites": false,
    "effect": "allow"
  }'
```
</RequestExample>
