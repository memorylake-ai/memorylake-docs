---
title: "Set Access Group Permissions"
description: "Replaces the group's own permission list; [] removes every one of them"
---

```
PUT /openapi/memorylake/admin/v1/access-groups/{group_id}/permissions
```

Replaces the group's own permission list; [] removes every one of them. The base role or base group stays as it is. Only permissions in GET /permission-catalog?grantable_to=access_group are accepted. Sending If-Match also requires view: the current list is read to compare.

The response carries an `ETag` header (the same value a GET of this resource returns). Send it back in `If-Match` to make the write conditional: when the resource has changed in the meantime the write is refused with 412 and nothing is changed. The check narrows, but does not fully close, the window for a concurrent overwrite — two writers that pass it at the same instant can both write.

<Note>
**Permission required:** `access_group:manage`

- When you send `If-Match` (the current list is read to compare): `access_group:view`
- Changes that give someone an admin role, or that reduce what an admin can reach, also require the team owner or an admin.
</Note>

### Path Parameters

<ParamField path="group_id" type="string" required>
Identifier
</ParamField>

### Headers

<ParamField header="If-Match" type="string">
Optional. The ETag from [Get Access Group](/features/memorylake/api-reference/access-control/get-access-group) or a previous [Set Access Group Permissions](/features/memorylake/api-reference/access-control/set-access-group-permissions). The write is refused with 412 when the group's permissions have changed since; omit it to overwrite unconditionally.
</ParamField>

### Request Body

The group's complete permission list; [] removes all of them. The base role or base group is unaffected.
