## API Overview

The MemoryLake API lets you feed documents and conversations into a project, automatically extract structured facts, and search across all memory sources with natural language. Use it to build AI applications with long-term memory.

## Base URL

```
https://app.memorylake.ai/openapi/memorylake
```

## Authentication

All API requests require a Bearer token in the `Authorization` header. See [Authentication](/features/memorylake/api-reference/authentication) for details.

## Common Patterns

### Response Format

All responses follow this structure:

```json
{
  "success": true,
  "message": "Operation completed successfully",
  "data": {
    // Response payload
  }
}
```

Error responses:
```json
{
  "success": false,
  "message": "Error description",
  "error_code": "ERROR_CODE"
}
```

### Your own identifiers

Every resource you create has two identifiers. `id` is minted here — a prefix and 32 hex characters,
like `actor-7b5470549febfaca2acc5a3ebcaa2138`. `custom_id` is the one you bring: the identifier this
thing already has in your system.

Setting it means you do not have to store our id next to your record. Create an actor with the user
id your application already uses, and from then on you can address that actor by it:

```bash
# create with the id your system already has
curl -X POST .../api/v3/actors \
  -d '{"custom_id": "user-4471", "display_name": "Jane"}'

# and reach it by that id afterwards, with by_custom_id=true
curl .../api/v3/actors/user-4471?by_custom_id=true
```

<Note>
  **A `custom_id` must be unique within your tenant**, per kind of resource — two actors cannot share
  one, though an actor and a project may. Deleting a resource frees its `custom_id` for reuse.
</Note>

### Pagination

List endpoints use continuation-token pagination:

**Query Parameters**:
- `page_size`: Number of items per page
- `continuation_token`: Token from a previous response to fetch the next page

When the response has no `continuation_token`, there are no more pages.

### Idempotent requests

Write endpoints that change your team — creating a key, rotating it, inviting someone, changing a role — accept an optional `Idempotency-Key` header. Send any unique string, such as a UUID. Retrying with the same value within 24 hours replays the first response, errors included, instead of making the change again, and the replayed response carries `Idempotency-Replayed: true`. Reusing a value with different parameters, or while the first request is still running, is refused. A secret, such as a new API key, is returned only in the first response. Endpoints that accept the header list it under **Headers**.

```bash
curl -X POST 'https://app.memorylake.ai/openapi/memorylake/admin/v1/api-keys/{id}/rotate' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Idempotency-Key: 7c1d2e3f-0a9b-4c8d-b7e6-f5a4d3c2b1a0'
```

### Timestamps

All timestamps use ISO 8601 format:
```
2024-01-15T10:30:00Z
```

Fields documented as *Unix seconds* — on team, member, usage and billing endpoints, for example — are integers counting seconds since 1970-01-01 UTC.
