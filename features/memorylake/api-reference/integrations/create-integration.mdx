---
title: "Create IM Integration"
description: "Connects a DingTalk, WeCom, Feishu or Slack bot to an agent"
---

```
POST /openapi/memorylake/admin/v1/integrations
```

Connects a DingTalk, WeCom, Feishu or Slack bot to an agent. The integration is enabled at once and starts in status pending. DingTalk, Feishu and Slack credentials are verified with the platform before anything is saved (an access-token exchange or auth.test — no message is sent); WeCom credentials are checked by connecting, so follow status with [Get IM Integration](/features/memorylake/api-reference/integrations/get-integration). A bot can be connected only once. You also need write access to read_write_project_id and search access to each read-only project.

<Note>
**Permission required:** `workspace:integration_manage` on `workspace_id`

- When you set `read_write_project_id`: `project:mem_add` on `read_write_project_id`
- When you set `read_only_project_ids`: `project:mem_search` on `read_only_project_ids`
</Note>

### Headers

<ParamField header="Idempotency-Key" type="string">
Optional. Retrying with the same value replays the first result instead of creating a second integration. Credential values are not compared.
</ParamField>

### Request Body

<ParamField body="agent_id" type="string" required>
Agent that answers messages sent to the bot
</ParamField>

<ParamField body="channel" type="string" required>
IM platform. Must be enabled on this deployment. One of: `dingtalk`, `wecom`, `feishu`, `slack`.
</ParamField>

<ParamField body="credentials" type="object" required>
Write-only. dingtalk: appKey + appSecret; feishu: appId + appSecret; slack: botToken + appToken; wecom: botId + secret. DingTalk, Feishu and Slack credentials are verified with the platform before saving.
<Expandable title="Integration Credentials object">
  <ParamField body="credentials.appId" type="string">Feishu: App ID. Identifies the bot; cannot change after creation.</ParamField>
  <ParamField body="credentials.appKey" type="string">DingTalk: Client ID (AppKey). Identifies the bot; cannot change after creation.</ParamField>
  <ParamField body="credentials.appSecret" type="string">DingTalk: Client Secret (AppSecret). Feishu: App Secret.</ParamField>
  <ParamField body="credentials.appToken" type="string">Slack: App-Level Token (xapp-…) with connections:write.</ParamField>
  <ParamField body="credentials.botId" type="string">WeCom: Bot ID of the intelligent robot. Identifies the bot; cannot change after creation.</ParamField>
  <ParamField body="credentials.botToken" type="string">Slack: Bot User OAuth Token (xoxb-…). Apps with token rotation enabled are not supported.</ParamField>
  <ParamField body="credentials.secret" type="string">WeCom: Secret of the intelligent robot.</ParamField>
</Expandable>
</ParamField>

<ParamField body="name" type="string" required>
Display name
</ParamField>

<ParamField body="read_write_project_id" type="string" required>
Project that memories extracted from IM conversations are written to. Anyone who can message the bot can add to it.
</ParamField>

<ParamField body="workspace_id" type="string" required>
Workspace the integration belongs to. Cannot change later.
</ParamField>

<ParamField body="daily_message_limit" type="integer">
Maximum messages handled per day; omit or 0 = unlimited
</ParamField>

<ParamField body="dataset_ids" type="array">
Open-data datasets the agent may use
</ParamField>

<ParamField body="read_only_project_ids" type="array">
Additional projects searched (read only). Must not repeat read_write_project_id.
</ParamField>

<ParamField body="settings" type="object">
Channel-specific settings
<Expandable title="Integration Settings object">
  <ParamField body="settings.card_template_id" type="string">DingTalk only: AI card template id. Set it to stream replies into an interactive card; omit or send "" to reply with plain messages.</ParamField>
</Expandable>
</ParamField>

  <ResponseField name="id" type="string">Identifier of the integration</ResponseField>
  <ResponseField name="name" type="string">Display name</ResponseField>

  <ResponseField name="read_write_project_id" type="string">Project that memories extracted from IM conversations are written to</ResponseField>
  <ResponseField name="settings" type="object">
  Channel-specific settings
  <Expandable title="Integration Settings object">
    <ResponseField name="card_template_id" type="string">DingTalk only: AI card template id. Set it to stream replies into an interactive card; omit or send "" to reply with plain messages.</ResponseField>
  </Expandable>
  </ResponseField>
  <ResponseField name="status" type="string">Connection state. pending right after a create or a credential change until the first connection attempt; poll [Get IM Integration](/features/memorylake/api-reference/integrations/get-integration) to follow it. One of: `pending`, `connected`, `error`, `disabled`.</ResponseField>
  <ResponseField name="updated_at" type="integer">Last update time, Unix seconds</ResponseField>
  <ResponseField name="workspace_id" type="string">Workspace the integration belongs to. Fixed at creation.</ResponseField>
  <ResponseField name="status_error" type="string">Short normalized reason when status is error, for display (Chinese, the console's wording; it may change). Never contains the platform's raw response. Use status_error_code in programs.</ResponseField>
  <ResponseField name="status_error_code" type="string">Stable reason code, present whenever status_error is. credentials_invalid: the platform rejected the credentials (fix them); subscribe_rejected: WeCom refused the subscription — wrong credentials or the platform's rate limit, retried automatically; preempted: another connection took over the bot, usually the same bot connected from another environment; timeout / disconnected / connection_aborted / connection_failed: connection problems, retried automatically; dependency_unavailable: a service this deployment depends on is down, retried automatically; dependency_misconfigured: this deployment lacks something the channel needs (WeCom needs Redis) — contact the operator; internal_error: a fault on our side; unknown: the reason was recorded before codes existed, and is replaced on the next connection attempt. New codes may be added; treat an unrecognised one like connection_failed.</ResponseField>
</Expandable>
</ResponseField>
