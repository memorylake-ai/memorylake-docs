title: "Overview"
description: "Actors are the identity layer in MemoryLake — the subject of all memories"
---

An **Actor** represents a participant identity in MemoryLake. Every message in a conversation is attributed to an actor, and every fact extracted from those conversations is associated with one. Actors are the **subject of memory** — they are what MemoryLake "remembers about."

## Actor Types

The Actor API works with the people using your application. An actor you create here is a person —
there is nothing else to choose.

**An agent is not reachable through this API.** Agents have memories of their own, but you address
them through the [Agent](/features/memorylake/api-reference/agents/overview) endpoints, using the
agent's id. Nothing belonging to an agent is returned here, and an id that is not an actor's answers
`404`.

<Note>
  If you previously read an agent's memories through its identity actor, switch to the agent id. It
  is the same memories, named the way everything else names them.
</Note>

## How Actors Work

1. **Create** an actor globally with a `custom_id` that maps to your user ID
2. **Bind** the actor to one or more workspaces
3. **Use** the actor's ID when [appending messages](/features/memorylake/api-reference/conversations/create-message) to conversations
4. **Query** the actor's accumulated facts via [Actor Facts](/features/memorylake/api-reference/facts/list-actor-facts)

## Where facts are stored

MemoryLake keeps facts at three scopes. Which one a fact belongs to decides where you read it back:

| Scope | What it remembers | Where you read it |
|---|---|---|
| **Actor facts** | A person, across every project in a workspace. *"Jane prefers dark mode"* | `/workspaces/{workspaceId}/actors/{actorId}/facts` |
| **Agent facts** | An agent, across every project in a workspace. *"This agent answers in French"* | `/workspaces/{workspaceId}/agents/{agentId}/facts` |
| **Project facts** | One project, whoever contributed it. *"Q1 revenue was $12.5M"* | `/workspaces/{workspaceId}/projects/{projectId}/memories/facts` |

Actor and agent facts follow their subject across projects — that is what gives each person, and each
agent, a memory of its own throughout your application. Project facts stay with the project.

<Note>
  **An agent's facts are read on the agent, by its agent id** — not through the actor endpoints above.
  The two paths are symmetrical, so anything you can do with a person's facts you can do with an
  agent's; only the id and the path differ.
</Note>

## Endpoints

| Operation | Method | Path |
|-----------|--------|------|
| [List Actors](/features/memorylake/api-reference/actors/list-actors) | `GET` | `/api/v3/actors` |
| [Create Actor](/features/memorylake/api-reference/actors/create-actor) | `POST` | `/api/v3/actors` |
| [Get Actor](/features/memorylake/api-reference/actors/get-actor) | `GET` | `/api/v3/actors/{id}` |
| [Update Actor](/features/memorylake/api-reference/actors/update-actor) | `PATCH` | `/api/v3/actors/{id}` |
| [Delete Actor](/features/memorylake/api-reference/actors/delete-actor) | `DELETE` | `/api/v3/actors/{id}` |
| [Bind to Workspace](/features/memorylake/api-reference/actors/bind-actor) | `POST` | `/api/v3/workspaces/{id}/actors` |
| [List in Workspace](/features/memorylake/api-reference/actors/list-workspace-actors) | `GET` | `/api/v3/workspaces/{id}/actors` |
