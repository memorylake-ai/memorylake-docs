---
title: "Create Team"
description: "Creates a new org team owned by the API key's owner (not by this key's team)"
---

```
POST /openapi/memorylake/admin/v1/teams
```

Creates a new org team owned by the API key's owner (not by this key's team). The owner must be a person who can sign in: keys of virtual members are refused (403). If issue_api_key is true, the response includes a new owner API key for that team; its secret is returned only on the first response — a retry with the same Idempotency-Key replays the team and the key's metadata without the secret. Without an Idempotency-Key, a retry creates a second team. Creating a team counts toward the owner's team limit (409 RESOURCE_LIMIT_EXCEEDED when reached) and grants the free plan when available. 403 also when team creation is disabled on this deployment.

<Warning>
**High-risk operation.** It takes effect immediately. Read what it changes, above, before you call it.
</Warning>

<Note>
**Permission required:** none — any member's key can call this
</Note>

### Headers

<ParamField header="Idempotency-Key" type="string">
Optional. Retrying with the same value replays the first result. If an API key was issued, its secret is returned only on the first response.
</ParamField>

### Request Body

<ParamField body="name" type="string" required>
Display name for the new org team
</ParamField>

<ParamField body="api_key_name" type="string">
Display name for the optional owner API key. Defaults to the team name plus ' API key'.
</ParamField>

<ParamField body="issue_api_key" type="boolean">
If true, also create an owner API key in the new team and return its secret once.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST 'https://app.memorylake.ai/openapi/memorylake/admin/v1/teams' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Idempotency-Key: 7c1d2e3f-0a9b-4c8d-b7e6-f5a4d3c2b1a0' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Example name",
    "api_key_name": "Example api key",
    "issue_api_key": true
  }'
```
</RequestExample>

### Errors

Errors answer with `success: false`, a `message` and an `error_code`. See [Error Codes](/features/memorylake/api-reference/errors) for every code.

| Status | Meaning |
| --- | --- |
| `400` | A parameter or the body is invalid |
| `401` | The API key is missing, invalid, disabled or expired |
| `403` | The key is not allowed to do this |
| `409` | The request conflicts with the current state, e.g. a duplicate or a limit reached |
| `422` | The body or a parameter failed validation |
| `429` | Too many requests. Wait for the time in `Retry-After` |
| `500` | Server-side error |
| `503` | Temporarily unavailable. Retry later |
