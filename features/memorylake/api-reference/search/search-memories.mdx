---
title: "Search Memories"
description: "Search across all memory sources in a workspace using natural language"
---

```
POST /openapi/memorylake/api/v3/workspaces/{workspaceId}/memories/search
```

Searches across all memory sources in a workspace — documents and facts — using a natural language query. Results are grouped by source type so you can present each category separately or merge them in your UI. Documents are searched only in the projects you list in `project_ids`; the other optional filters choose actors, agents, or memory types.

<Note>
**Permission required:** `workspace:memory_search` on the workspace, plus one per thing you name — on each project in `project_ids`: `project:mem_search` and `project:doc_search`; on each actor in `actor_ids`: `workspace_actor:fact_search`; on each agent in `agent_ids`: `workspace_agent:fact_search`. Naming something you may not search refuses the whole request.
</Note>

### Path Parameters

<ParamField path="workspaceId" type="string" required>
Workspace identifier
</ParamField>

### Request Body

<ParamField body="query" type="string" required>
Natural language search query
</ParamField>

<ParamField body="project_ids" type="array of strings">
Projects to search. Documents are searched only in the projects listed here: when omitted, no project is searched and `documents` comes back empty. Facts are still searched for the actors and agents in the request, or for your own actor when neither `actor_ids` nor `agent_ids` is set.
</ParamField>

<ParamField body="actor_ids" type="array of strings">
Limit search to memories associated with specific actors
</ParamField>

<ParamField body="agent_ids" type="array of strings">
Limit search to memories belonging to specific agents.
</ParamField>

<ParamField body="memory_types" type="array of strings">
Filter results by memory type. Accepted values: `document`, `fact`. When omitted, all types are searched.
</ParamField>

<ParamField body="top_k" type="integer" default="10">
Maximum number of results to return in total (1–1000). One budget is shared by all searched memory types, not a limit per type: `top_k=5` may come back as five documents, or as three documents and two facts, depending only on what best answers the query. Fewer results may be returned.
</ParamField>

<ParamField body="search_effort" type="string">
How thoroughly to search, trading result quality for speed:

- `max` — run the full search.
- `high` — do not expand the query from stored facts, and use a lighter final ranking. Typically answers noticeably faster than `max`.
- `low` — like `high`, and also skip model-based understanding of the query and narrow recall, for the fastest answers.

Lower levels may return fewer or different results for the same query. When omitted, the default level applies. Any other value returns `400`.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST 'https://app.memorylake.ai/openapi/memorylake/api/v3/workspaces/ws-8001856949ad4f6a5b6226f415ffa877/memories/search' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "query": "What were the quarterly revenue figures?",
    "project_ids": ["proj-b93e8d95a8705bcc4ec42a65ba4cc7f8"],
    "memory_types": ["document", "fact"],
    "top_k": 10
  }'
```
</RequestExample>

### Response

<Expandable title="Search results grouped by source type">
  <ResponseField name="documents" type="array">
  Document search results, grouped by source document
  <Expandable title="DocumentSearchResult">
    <ResponseField name="document_id" type="string">Document identifier</ResponseField>
    <ResponseField name="project_id" type="string">ID of the project this document belongs to, always one of the `project_ids` you sent. Use it with `document_id` to address the document afterwards, e.g. to [get](/features/memorylake/api-reference/v3-documents/get-document) or download it.</ResponseField>
    <ResponseField name="document_name" type="string">Display name of the document</ResponseField>
    <ResponseField name="file_name" type="string">Original file name</ResponseField>
    <ResponseField name="document_summary" type="string">Summary of the document</ResponseField>
    <ResponseField name="source_type" type="string">Source type of the document (e.g. `upload`, `connector`)</ResponseField>
    <ResponseField name="sheet_name" type="string">Worksheet name, if the document is a workbook</ResponseField>
    <ResponseField name="items" type="array">
    Matched content items within the document
    </ResponseField>
  </Expandable>
  </ResponseField>
  <ResponseField name="facts" type="array">
  Fact search results
  <Expandable title="FactSearchResult">
    <ResponseField name="id" type="string">Fact identifier</ResponseField>
    <ResponseField name="fact" type="string">The fact text</ResponseField>
    <ResponseField name="score" type="number">Relevance score</ResponseField>
    <ResponseField name="metadata" type="object">Additional metadata associated with the fact</ResponseField>
    <ResponseField name="created_at" type="string">Creation timestamp</ResponseField>
    <ResponseField name="updated_at" type="string">Last update timestamp</ResponseField>
    <ResponseField name="owner" type="object">
    The project, actor or agent this fact belongs to, reported by the ID the request used for it. When the request sets neither `actor_ids` nor `agent_ids`, your own actor is searched too — even if `project_ids` is set — and its facts are reported as that actor. Use it to address the fact afterwards, e.g. to read it; updating or deleting a fact also requires its owner to still exist.
    <Expandable title="Owner object">
      <ResponseField name="type" type="string">Owner type: `project`, `actor` or `agent`</ResponseField>
      <ResponseField name="id" type="string">Owner ID: a project ID when `type` is `project`, an actor ID when `type` is `actor`, an agent ID when `type` is `agent`</ResponseField>
    </Expandable>
    </ResponseField>
  </Expandable>
  </ResponseField>
</Expandable>
</ResponseField>
