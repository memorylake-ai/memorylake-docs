title: "List Usage Records"
description: "Lists individual consumption records, newest first: one per billed model request or platform operation, with tokens and the consumption charged in tokens"
---

```
GET /openapi/memorylake/admin/v1/usage/records
```

Lists individual consumption records, newest first: one per billed model request or platform operation, with tokens and the consumption charged in tokens. Consumption is attributed to members — to tell applications apart, give each its own virtual member. Records are near real-time; [Get Usage](/features/memorylake/api-reference/usage/get-usage) reads aggregates refreshed every few minutes, so the two can briefly disagree. With log:read_all the list covers the team; a caller holding only log:read_self sees their own records, and filtering by another member's principal_id is refused. The window defaults to the last 7 days and may span at most 92 days. Unlike other lists this one returns no total — page with continuation_token until it is absent. Rate limit: 20 requests per minute per key by default, counted separately from all other operations. When paging through many records, use the largest page_size (100).

<Note>
**Permission required:** `log:read_all` (whole team) or `log:read_self` (your own only)

- When you filter by another member's `principal_id`: `log:read_all`
</Note>

### Query Parameters

<ParamField query="page_size" type="integer" default="20">
Number of items per page (1–100)
</ParamField>

<ParamField query="continuation_token" type="string">
Token from the previous page. Opaque — do not construct or parse it. Send the same filters with it.
</ParamField>

<ParamField query="start_time" type="integer">
Earliest record time to include, Unix seconds (inclusive). Defaults to 7 days before end_time.
</ParamField>

<ParamField query="end_time" type="integer">
Latest record time, Unix seconds (exclusive). Defaults to now. The window may span at most 92 days.
</ParamField>

<ParamField query="model" type="array">
Only records for these models or platform operations (files_process, memory_input, retrieval_call, search_call). Repeat the parameter for several.
</ParamField>

<ParamField query="kind" type="string">
model_call: model requests. platform_task: platform operations such as file processing and memory writes. Omit for both.
</ParamField>

<ParamField query="principal_id" type="array">
Only records of these members. Repeat the parameter for several. A caller limited to their own records may only pass their own id.
</ParamField>

<ParamField query="request_id" type="string">
Only the record of this request id.
</ParamField>

<RequestExample>
```bash cURL
curl -X GET 'https://app.memorylake.ai/openapi/memorylake/admin/v1/usage/records' \
  -H 'Authorization: Bearer sk_xxxxxx'
```
</RequestExample>

### Errors

Errors answer with `success: false`, a `message` and an `error_code`. See [Error Codes](/features/memorylake/api-reference/errors) for every code.

| Status | Meaning |
| --- | --- |
| `400` | A parameter or the body is invalid |
| `401` | The API key is missing, invalid, disabled or expired |
| `403` | The key is not allowed to do this |
| `422` | The body or a parameter failed validation |
| `429` | Too many requests. Wait for the time in `Retry-After` |
| `500` | Server-side error |
