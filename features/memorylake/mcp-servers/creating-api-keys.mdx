---
title: "Connect via MCP"
description: "Connect Claude Code, Codex, Cursor, and other MCP clients to MemoryLake with standard OAuth2"
---

MemoryLake runs a **remote MCP server** that any MCP-capable client can connect to over HTTP. Authorization uses standard **OAuth2** — you never paste a secret into a config file, and you choose which workspace and boundary the client may access on the consent screen.

## Server URL

```text
https://app.memorylake.ai/memorylake/mcp/v2
```

In the [console](https://app.memorylake.ai), open a workspace and select the **MCP** tab: it shows this URL with a copy button, along with ready-made setup steps for each client. (The old **Integrations → MCP** link now opens this tab.)

<Info>
There is no project picker on the connect page. When you authorize, the consent screen asks you to pick **Personal / Team**, a **Workspace**, and a **Memory boundary** — that choice decides what the client can read and write.
</Info>

## Connect Your Client

<Tabs>
<Tab title="Claude Code">
Add the server in your terminal (`--scope user` is optional and makes it available in every project):

```bash
claude mcp add --transport http --scope user memorylake https://app.memorylake.ai/memorylake/mcp/v2
```

Then authorize: run `claude` to open a session, type `/mcp`, select `memorylake`, and choose **Authenticate** — your browser opens the authorization page. Claude Code has no standalone login command; authorization is triggered from inside a session.

Verify with `claude mcp list`: the `memorylake` line should read `✓ Connected`.
</Tab>

<Tab title="Codex">
Add the server in your terminal. `--url` marks it as a streamable HTTP server, which uses OAuth by default:

```bash
codex mcp add memorylake --url https://app.memorylake.ai/memorylake/mcp/v2
```

This writes an `[mcp_servers.memorylake]` block into `~/.codex/config.toml`. Then sign in — your browser opens the authorization page:

```bash
codex mcp login memorylake
```

Verify with `codex mcp list`.
</Tab>

<Tab title="Cursor">
Add this to `~/.cursor/mcp.json` (all projects) or `.cursor/mcp.json` inside a project. Cursor reloads on save. The console's **MCP** tab also has an **Add to Cursor** button that writes it for you.

```json
{
  "mcpServers": {
    "memorylake": {
      "url": "https://app.memorylake.ai/memorylake/mcp/v2"
    }
  }
}
```

Open **Settings → MCP**; `memorylake` shows that it needs login. Click to log in and your browser opens the authorization page.
</Tab>

<Tab title="VS Code">
Add this to `.vscode/mcp.json` in your workspace, or run **MCP: Add Server** from the command palette. The console's **MCP** tab also has an **Add to VS Code** button.

```json
{
  "servers": {
    "memorylake": {
      "type": "http",
      "url": "https://app.memorylake.ai/memorylake/mcp/v2"
    }
  }
}
```

VS Code prompts for authorization when the server starts; confirm and your browser opens the authorization page.
</Tab>

<Tab title="Claude Desktop">
Open **Settings → Connectors → Add custom connector** and paste the server URL above. Claude Desktop opens an authorization window once you confirm — follow the prompts to sign in and grant access.
</Tab>

<Tab title="Other clients">
Any MCP client that supports remote servers with OAuth 2.1 works. Point it at the server URL above — no API key, no custom headers. On the first `401` the client discovers the authorization server, registers itself dynamically, runs the browser flow with PKCE, and refreshes the token on its own.
</Tab>
</Tabs>

## What Connected Clients Can Do

Once authorized, the client gets tools for searching and analyzing the content in scope:

| Tool | What it does |
|---|---|
| `search_memory` | Hybrid keyword + semantic search across memories and documents |
| `fetch_memory` | Fetch detailed metadata and download links for specific results |
| `get_memorylake_metadata` | Overview — file counts by type, spreadsheet sheet names, document stats |
| `create_memory_code_runner` / `run_memory_code` | Sandboxed Python (pandas, numpy, …) over the files in scope, with state persisting across calls |
| `nl_query_database` | Natural-language SQL over a connected database, where one is configured |

OpenAI-protocol clients are automatically served simplified `search` / `fetch` variants of the same tools — one endpoint adapts to the client.

These tools read and analyze; they do not modify or delete your documents and memories.

## Managing Access

- **Switch workspace**: the personal/team space and workspace are fixed in the token when you authorize. To pick a different one, remove the MCP server from your client, add it again, and authorize again (for Claude Code: `claude mcp remove memorylake`, then the `claude mcp add` command above, then **Authenticate** via `/mcp`).
- **Revoke**: go to **Account settings → Sign-in & security → Authorized apps** in the console and revoke the client. To also remove it from the client, for Claude Code run `claude mcp remove memorylake`.
- **Token lifetime**: access tokens are short-lived and refreshed automatically by the client.

<Note>
Earlier versions of MemoryLake used a v1 MCP endpoint with a project-scoped key embedded in the URL (`…/mcp/v1?apikey=…`). That flow has been retired: the console no longer creates v1 endpoints or keys, and API keys cannot be used to connect to MCP. The v1 endpoint is still served for existing integrations only; set up new connections with the v2 URL above. API keys are still used for the REST API.
</Note>

## Troubleshooting

<AccordionGroup>
<Accordion title="Client can't connect">
Confirm the URL ends in `/mcp/v2` and the client is configured for a **remote HTTP** MCP server (not a local command). Make sure the client supports OAuth2 for MCP — older clients that only accept static tokens cannot use the v2 endpoint.
</Accordion>

<Accordion title="Authorization succeeds but no tools appear">
Check that you completed the personal/team, workspace, and memory boundary selection on the consent screen, then authorize again (Claude Code: `/mcp` → **Authenticate** in a session; Codex: `codex mcp login memorylake`; other clients: log in again from their MCP settings).
</Accordion>

<Accordion title="The browser did not open the authorization page">
The terminal prints a link containing `/oauth2/mcp/authorize` — copy it into your browser manually. This is almost always the case over SSH or in remote development environments.
</Accordion>

<Accordion title="Tools return nothing">
The memory boundary you authorized may point at an empty project. Confirm in the console that the projects in that boundary actually contain documents or memories.
</Accordion>

<Accordion title="I don't see MCP in my console">
MCP availability depends on your deployment. If a workspace has no **MCP** tab, or the tab says OAuth2 MCP is not enabled, contact [support@memorylake.ai](mailto:support@memorylake.ai).
</Accordion>
</AccordionGroup>
