<AccordionGroup>
<Accordion title="Do I need to change my code?">
Only the base URL, a `boundary_id` query parameter, and — in BYOK mode — one header. Your prompts, streaming, tool calls, and response handling stay identical, because Memory Router speaks the same API as your provider.
</Accordion>

<Accordion title="What is a Boundary and do I always need one?">
A Boundary is the memory scope for a conversation — it binds requests to a workspace, project(s), and actors so the Router knows whose memory to read and write. You create it once in the console and pass its id as `?boundary_id=` on each call. Requests without a `boundary_id` still work, but pass through with memory disabled.
</Accordion>

<Accordion title="Which providers and models are supported?">
OpenAI (Chat Completions, Responses, Images) and Anthropic (Messages) protocols. In hosted mode, GPT, o-series, and Claude models — plus image models such as `gpt-image-1` — are built in and callable by their native names; the console's **Available Models** page lists them all. No embedding models are available yet. See [Deployment Modes](/features/memory-router/deployment-modes#supported-providers) for the current matrix.
</Accordion>

<Accordion title="Can I generate images?">
Yes. Call image models such as `gpt-image-1` through the OpenAI Images endpoint (`images.generate` in the OpenAI SDKs), with the same base URL and key as chat models. Image generation does not use memory. See [Image Generation](/features/memory-router/image-generation).
</Accordion>

<Accordion title="What is the difference between BYOK and MemoryLake-hosted?">
BYOK (Bring Your Own Key) means you supply your own provider key plus a MemoryLake key — model billing and rate limits stay with your provider account, while memory is billed to your MemoryLake balance. MemoryLake-hosted needs only a MemoryLake key: we run the major models for you, so you skip provider sign-up entirely. Both modes use the same endpoints; the difference is which keys you send.
</Accordion>

<Accordion title="In BYOK mode, is my provider key safe?">
Yes. Your provider key is encrypted in transit and forwarded to the provider on each call. MemoryLake never stores, logs, or reuses it — the design is stateless, per-request passthrough with zero server-side key storage.
</Accordion>

<Accordion title="What happens if the memory service is unavailable?">
The gateway returns `502 Bad Gateway` for that call — retry with backoff, and keep a fallback to a direct provider call if your application requires strict availability. Memory *writes* are asynchronous, so a slow memory store never delays a successful response. See [Observability](/features/memory-router/observability#error-contract) for the full error contract.
</Accordion>

<Accordion title="Does memory add latency to my calls?">
Memory recall happens before the model call and is optimized for low overhead; memory extraction and storage happen asynchronously after the response is returned, so writing memories never adds latency.
</Accordion>

<Accordion title="Is the memory shared with the MemoryLake API?">
Yes. The Router and the [MemoryLake API](/features/memorylake/overview) operate on the same memory pool, so anything stored one way is retrievable the other — and visible in the console.
</Accordion>

<Accordion title="How do I get access?">
Sign in to the [console](https://app.memorylake.ai), create an API key, and open **Integrations → Memory Router API** to create a Boundary and copy ready-made snippets. The [Quickstart](/features/memory-router/quickstart) walks through it.
</Accordion>
</AccordionGroup>
