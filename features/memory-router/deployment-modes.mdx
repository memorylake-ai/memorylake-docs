title: "Deployment Modes"
description: "Connect with your own provider key (BYOK) or with MemoryLake-hosted models — same memory layer either way"
---

Memory Router works two ways. Unlike proxies that force you to bring your own key, you can keep your provider account **or** let MemoryLake run the models for you. Both modes share the same endpoints — the difference is which keys you send. Everything else — prompts, streaming, tool calls — stays the same.

## Endpoints

| Protocol | Endpoint |
| --- | --- |
| OpenAI · Chat Completions | `POST https://app.memorylake.ai/openapi/memorylake/router/openai/v1/chat/completions` |
| OpenAI · Responses | `POST https://app.memorylake.ai/openapi/memorylake/router/openai/v1/responses` |
| OpenAI · Embeddings | `POST https://app.memorylake.ai/openapi/memorylake/router/openai/v1/embeddings` |
| OpenAI · Images | `POST https://app.memorylake.ai/openapi/memorylake/router/openai/v1/images/generations` |
| Anthropic · Messages | `POST https://app.memorylake.ai/openapi/memorylake/router/anthropic/v1/messages` |

Append `?boundary_id=<id>` to enable memory on a request — see [How It Works](/features/memory-router/how-it-works#boundaries-define-the-scope). `boundary_id` does not apply to Images. No embedding models are available yet, so the Embeddings endpoint is not usable for now. Every parameter is listed in the [API Reference](/features/memory-router/api-reference/overview). The earlier endpoints without `/openapi/memorylake/router` (such as `https://app.memorylake.ai/openai/v1`) keep working the same way; new integrations should use the paths above.

<Note>
With the Anthropic SDK, set `base_url` to `https://app.memorylake.ai/openapi/memorylake/router/anthropic` (without `/v1`) — the SDK appends `/v1/messages` itself.
</Note>

## MemoryLake-hosted

No provider account required. MemoryLake runs the major models for you, so a single MemoryLake API key is all you need to start.

- One key for everything — nothing else to sign up for.
- GPT, o-series, and Claude models built in and ready to call by their native names, plus image models such as `gpt-image-1` for [image generation](/features/memory-router/image-generation).
- The simplest possible way to ship with memory.

**Keys:** MemoryLake key only, in the native auth header (`Authorization: Bearer` for OpenAI-style calls, `x-api-key` for Anthropic)

```ts TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://app.memorylake.ai/openapi/memorylake/router/openai/v1",
  apiKey: process.env.MEMORYLAKE_API_KEY,
});

// Pick any built-in model by its native name, e.g. "gpt-4o-mini" or "claude-haiku-4-5".
```

## BYOK — Bring Your Own Key

Use your own provider account. Your provider key is encrypted in transit, forwarded to the provider per call, and never stored on our servers.

- Keep your existing OpenAI / Anthropic account.
- Model usage is billed to your provider account, under your rate limits.
- Key is encrypted + passthrough only — never persisted or logged.
- You can call the models listed under **Available Models** in the console.

**Keys:** your provider key in the provider's **native** auth header + MemoryLake key in the `x-memorylake-api-key` header

```ts TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://app.memorylake.ai/openapi/memorylake/router/openai/v1",
  apiKey: process.env.OPENAI_API_KEY,        // your provider key
  defaultHeaders: {
    "x-memorylake-api-key": process.env.MEMORYLAKE_API_KEY,
  },
});
```

<Info>
The native auth header differs by protocol: OpenAI-style calls use `Authorization: Bearer <key>`; Anthropic calls use `x-api-key: <key>`. In BYOK mode your provider key goes there, and the MemoryLake key always rides in `x-memorylake-api-key`.
</Info>

## Choosing a Mode

| | MemoryLake-hosted | BYOK |
| --- | --- | --- |
| Provider account | Not required | Required (yours) |
| Keys | MemoryLake key only | Provider key + MemoryLake key |
| Model billing & rate limits | Handled by MemoryLake | Stay with your provider account |
| Memory billing | Your MemoryLake balance | Your MemoryLake balance |
| Best for | Fastest path to ship with memory | Teams with existing provider contracts and quotas |

## Key Safety, by Design

<Warning>
In BYOK mode your provider key is encrypted in transit and passed straight through to the provider on every call. MemoryLake never stores, logs, or reuses it — the design is stateless, per-request passthrough with zero server-side key storage.
</Warning>

## Supported Providers

| Provider | BYOK | Hosted |
| --- | --- | --- |
| OpenAI / GPT (Chat Completions & Responses) | ✅ | ✅ |
| Anthropic / Claude (Messages) | ✅ | ✅ |
| OpenAI image models (Images) | ✅ | ✅ |
| Embeddings | — | — (no models yet) |

Additional providers and protocols are added over time; the console's **Available Models** page always reflects the current catalog.

<Note>
Both modes need a MemoryLake balance: memory is billed to it in BYOK mode too, and a call is refused with `402` when the balance is too low.
</Note>
